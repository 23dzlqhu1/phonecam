## 2. 修复内容

### 2.1 A1 — TcpStreamServer 客户端断开后重接

**根因**: 客户端断开后 server 端 InputStream 不会主动 EOF, server 不知情, 仍持续 sendPacket, 触发 "Broken pipe" 日志风暴.

**修复** ([`TcpStreamServer.kt`](file:///d:/PhoneCam/phone_native/app/src/main/java/com/phonecam/nativeapp/TcpStreamServer.kt)):

1. accept() 循环用 `client.getInputStream().read()` 阻塞, 客户端 close 时 read()=-1 触发断开检测
2. sendPacket() 失败时立即 close socket + 清空 clientSocket, 避免日志风暴
3. SO_REUSEADDR=true 解决 TIME_WAIT 内无法 bind 同端口

**核心代码**:

```kotlin
// accept 循环: 一个 client 断开后接下一个
while (running) {
    val client: Socket = serverSocket.accept()  // 阻塞等客人
    onEvent("[3.2.0.3h] 客户端已连接: ${client.remoteSocketAddress}")

    // 阻塞等客户端断开
    val monitor = client.getInputStream()
    val buf = ByteArray(1024)
    while (running && client.isConnected && !client.isClosed) {
        val n = try { monitor.read(buf) } catch (ie: Exception) { break }
        if (n == -1) break  // 对端 close
    }

    try { client.close() } catch (_: Exception) {}
    if (clientSocket === client) clientSocket = null
    onEvent("[3.2.0.3h] 客户端已断开: 等待下一个连接")
}

// sendPacket: 失败时静默关闭
fun sendPacket(packet: ByteArray): Boolean {
    val client = clientSocket ?: return false  // null 时静默
    return try {
        synchronized(client) { client.getOutputStream().apply { write(packet); flush() } }
        true
    } catch (e: Exception) {
        onEvent("[3.2.0.3h] sendPacket 客户端断开: ${e.message}")
        try { client.close() } catch (_: Exception) {}
        if (clientSocket === client) clientSocket = null
        false
    }
}
```

## 6. 批次 3.2.0.3h-hotfix — 端到端真机联调 Bug 修复

**日期**: 2026-06-09 (续)
**目的**: 完成端到端真机联调 (3.2.0.3h 文档只验证了单项功能, 端到端联调未做), 修复发现的 2 个关键 bug.

### 6.1 Bug A: PC 端 receiver 头解析错位

**症状**:
- 推流启动成功 (手机端 30 fps 编码, 12000+ 帧)
- PC 端 phonecam.py 显示 "已连接, 开始接收 PCP 帧", 但 FPS 永远 = 0, 永远不报错, 永远不重连
- netstat 显示 TCP ESTABLISHED
- 持续 4+ 分钟没任何数据包被 PC 端正确解析

**根因** ([`receiver.py:259-285`](file:///d:/PhoneCam/desktop/receiver.py#L259-L285)):
```python
# 旧代码 (错的):
first5 = bytearray(5)
self._recv_exact(sock, first5, 5)        # ← 只在循环外读 1 次
...
while self._running:
    self._recv_exact(sock, header_buf, header_size - 5)
    full_header = bytes(first5) + bytes(header_buf)  # ← 第 2 个包开始 magic 错位
```

- 第 1 个包: 读 5 字节 (magic+version), 再读 27 字节 → 拼 32 字节 ✓
- 第 2 个包起: **不读新的 5 字节**, 直接读 27 字节, 那 27 字节实际是第 2 个包的 byte 6-32
- `full_header` = 旧 first5 (包 1 magic) + 包 2 byte 6-32 → 永远解析失败
- 但 `recv_into` 是阻塞的, 没数据就一直等, **不抛异常**, PC 端看起来"卡住"

**修复**:
```python
# 新代码 (批次 3.2.0.3h-hotfix):
first5 = bytearray(5)
header_buf = bytearray(32)
while self._running:
    # 每个包都重新读 5 字节 (magic + version), 不再错位
    self._recv_exact(sock, first5, 5)
    magic = bytes(first5[:4])
    if magic != MAGIC:
        raise ValueError(...)
    version = first5[4]
    ...
    self._recv_exact(sock, header_buf, header_size - 5)
    full_header = bytes(first5) + bytes(header_buf[:header_size - 5])
```

### 6.2 Bug B: adb forward 被误用为 adb reverse

**症状**:
- 手机端 9999 端口被 `adb reverse` 占用 (LISTEN), 状态显示 `*:9999 LISTEN` 但 phonecam 进程查不到
- StreamingService TcpStreamServer.bind(0.0.0.0:9999) 失败
- 错误日志: `java.net.BindException: EADDRINUSE`

**根因**:
- `adb reverse tcp:9999 tcp:9999` 的语义是: adbd 在**手机端** listen 9999, 把手机连接转给 PC
- 但我们的架构是: **手机端做 server** (TcpStreamServer.listen 9999), PC 端做 client 主动连
- adb reverse 的方向与架构矛盾, 反向占用了手机端 9999

**修复**:
- 撤掉 `adb reverse`, 改用 `adb forward`:
  ```
  adb forward tcp:9999 tcp:9999
  ```
  语义: PC 端 listen 9999, PC 端进程连 9999 时, adb 把连接转给手机端 127.0.0.1:9999
- 与架构一致: 手机 listen 9999, PC 主动 connect 9999
