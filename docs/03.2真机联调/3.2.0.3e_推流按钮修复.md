# MVP-2 批次 3.2.0.3e 真机联调记录

> 设备: Oplus PLC110 (ColorOS 14, Android 14) + Windows 11 PC
> 日期: 2026-06-09
> 目标: 修复真机联调时推流按钮文字错误 + ADB tap 触发长按事件

## 背景

3.2.0.3d 完成后, PC 端 `phonecam.py --connect` 链路已通, 开始真机联调。
点手机推流按钮后, 推流没启动, 排查发现两个 Bug。

## Bug 1: 推流按钮初始文字错误

`activity_main.xml` 中 `btnPush` 的 `android:text` 还在调试阶段
"拍 1 帧 (3.2 真实)", 而不是 "推流"。

### 修复

把 `btnPush` 的 `android:text` 改为 `@string/layer_c_btn_start` ("推流")。

## Bug 2: ADB tap 触发长按事件

修复按钮文字后, 用 `adb shell input tap 636 2550` 推流, 推流没启动。

### 排查

- 用 `uiautomator dump` + `dumpsys window` 查 `btnPush` 的实际 bounds:
  `[168,2229][1104,2453]` → 中心坐标 (636, 2341)
- 用 (636, 2341) 重试 → 推流启动成功, 但很快就停
- 推测 Oplus ColorOS 对 `input tap` 的处理是长按, 触发 `onLongClick` 后释放,
  按下/弹起之间产生 "长按" 事件, 推流状态机误判

### 修复

注册 BroadcastReceiver 接收 `com.phonecam.START_STREAMING` /
`com.phonecam.STOP_STREAMING` 广播, ADB 用 `am broadcast` 触发推流,
绕开按钮点击:

```kotlin
val streamFilter = IntentFilter().apply {
    addAction("com.phonecam.START_STREAMING")
    addAction("com.phonecam.STOP_STREAMING")
}
val streamReceiver = object : BroadcastReceiver() {
    override fun onReceive(ctx: Context, intent: Intent) {
        when (intent.action) {
            "com.phonecam.START_STREAMING" -> startStreamingInThread()
            "com.phonecam.STOP_STREAMING"  -> stopStreamingInternal()
        }
    }
}
registerReceiver(streamReceiver, streamFilter)
```

```bash
adb shell am broadcast -a com.phonecam.START_STREAMING -p com.phonecam.nativeapp
```

## 后续: 3.2.0.3f

3.2.0.3e 用 BroadcastReceiver 启 startStreaming, 但被 Hans 冻结管理器
冻结了 `Streaming-Start-Thread` 子线程, 推流卡住。3.2.0.3f 改为
前台 Service (StreamingService) 解决。
