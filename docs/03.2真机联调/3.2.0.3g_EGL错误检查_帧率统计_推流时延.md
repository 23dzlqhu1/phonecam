## 背景

但还有 3 个痛点没解决:

3.2.0.3g 一次性解决这 3 个问题。

## 3.2.0.3g 方案

### A. EGL error check (EglRenderer.kt)

加 3 个错误统计变量 + checkGlError 检查:

```kotlin
@Volatile var eglErrorCount: Long = 0
@Volatile var eglSwapFailCount: Long = 0
@Volatile var drawCallCount: Long = 0

// drawYuv 各关键步骤后检查 (不抛异常, 让推流继续)
private fun checkGlError(op: String) {
    var err = GLES20.glGetError()
    while (err != GLES20.GL_NO_ERROR) {
        eglErrorCount++
        Log.w(TAG, "$op err=0x${Integer.toHexString(err)} (累计 $eglErrorCount)")
        err = GLES20.glGetError()
    }
}

// eglSwapBuffers 检查返回值
val swapped = EGL14.eglSwapBuffers(eglDisplay, eglSurface)
if (!swapped) {
    eglSwapFailCount++
    val err = EGL14.eglGetError()
    Log.w(TAG, "[3.2.0.3g] eglSwapBuffers 失败 #${eglSwapFailCount}: err=0x${Integer.toHexString(err)}")
}
drawCallCount++
```

**关键决策**: 不抛异常, 让推流继续; 仅 Log + 累加计数。统计会被主线程 statsTimer 读出来。

### B. 帧率统计 (StreamingService.kt)

加 4 个计数器 + 1s 定时打印 (主线程 Handler):

```kotlin
@Volatile var sFrameSubmitCount: Long = 0   // listener 调用 submitFrame 次数
@Volatile var sFrameEncodeCount: Long = 0   // EGL owner thread drawYuv 完成次数
@Volatile var sNaluOutputCount: Long = 0    // H264Encoder 吐出 NALU 次数
@Volatile var sStartTimeMs: Long = 0L       // 推流启动时间 (SystemClock.elapsedRealtime)

// 主线程 Handler 1s 定时, 推流期间持续打印
private val statsRunnable: Runnable = object : Runnable {
    override fun run() {
        if (!sActive) return
        val elapsedSec = (android.os.SystemClock.elapsedRealtime() - sStartTimeMs) / 1000.0
        val submitFps = sFrameSubmitCount / elapsedSec
        val encodeFps = sFrameEncodeCount / elapsedSec
        val naluFps = sNaluOutputCount / elapsedSec
        val sendFps = sNaluSentCount / elapsedSec
        val bps = sBytesSentCount * 8.0 / elapsedSec / 1_000.0
        val eglErr = sEglRenderer?.eglErrorCount ?: 0
        InAppLogStore.i(TAG, "[3.2.0.3g-STATS] T=${"%.1f".format(elapsedSec)}s 送帧=...fps 编码=...fps ...")
        statsHandler.postDelayed(this, 1000L)
    }
}
```

**关键点**:
- 3 个 ++ 不是线程安全的, 但每个变量都是单线程自己加自己读 (listener 加 sFrameSubmitCount, EGL owner thread 加 sFrameEncodeCount, encoder output thread 加 sNaluOutputCount), 实际读到的 fps 接近真实值
- 启动时 reset, 停推流时 stopStatsTimer
- 1s 一次, 不刷屏, logcat 能看清

### C. 推流时延 (PCP 协议升级 + 端到端同步)

**问题**: Camera2 `Image.getTimestamp()` 是 Android 单调时钟 (CLOCK_MONOTONIC, 纳秒, 设备启动后),
Python `time.monotonic_ns()` 是 PC 单调时钟 (纳秒, PC 启动后), 两者**基准点不同** (设备启动时间差),
不能直接相减。

**方案**:
1. PCP 协议头 24→32 字节, 新增 `pts_ns` (u64, Camera2 Image.getTimestamp 纳秒)
2. MainActivity listener 提交帧时把 `image.timestamp` 传给 StreamingService
3. StreamingService 把 `pts_ns` 写进 PCP header
4. PC 端 PcpReceiver 解析 32 字节头, 把 `pts_ns` 存入 `VideoFrame.pts_ns`
5. PC 端 phonecam.py 显示时:
   - 首次收到 `pts_ns` 时记 offset = `pc_monotonic_ns - pts_ns`
   - 之后 latency = `(pc_monotonic_ns - offset - pts_ns) / 1e6` ms

**协议兼容**: 新 receiver 先读 4 字节 magic + 1 字节 version, 决定 HEADER_SIZE:
- version=0x01 (老) → 24 字节头
- version=0x02 (新) → 32 字节头
老 app 推老协议, 新 receiver 仍能解码 (测试通过)。
