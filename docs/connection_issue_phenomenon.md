# G-024 端口转发与连接状态现象记录

## 现象描述

在 PC 端 GUI 启动后，系统尝试自动建立连接通道，但出现了 PC 与手机端连接状态的误判与卡滞，表现为以下具体现象：

### 1. PC 端 GUI 界面表现
* 界面顶部状态栏显示为灰色指示灯，文字提示为 **“正在搜索设备... 请确保手机 App 已启动推流”**。
* 中央预览区域持续显示 **“等待连接...”** 的黑色占位，无法正常显示或进入摄像头视频画面。

### 2. PC 端终端控制台日志表现
终端输出表明底层连接管理器已经成功初始化并完成了端口设置，但与 GUI 界面的状态不一致：
```
2026-06-11 13:24:40,208 [INFO] connection_manager: [ADB] 端口转发建立成功
2026-06-11 13:24:40,208 [INFO] connection_manager: [ADB] 反向代理就绪，等待手机端推流...
2026-06-11 13:24:40,208 [INFO] discovery: [mDNS] 监听中...
```
*控制台日志在此处停止，并没有出现 any `PcpReceiver` 的连接建立或流接收日志。*

### 3. 手机端 App 界面表现
* 在手机端点击「开始推流」后，按钮状态变为不可点击的灰色状态，文字显示为 **“连接中 (等 PC)..”** 并持续卡在该状态。
* 最终，推流由于长时间无数据交互而自动触发超时报错，显示推流失败。

---

## 状态不一致特征

* **PC 侧底层**：已执行完端口代理设置逻辑并通知状态更新。
* **PC 侧 UI**：状态依然停留在初始的 `SEARCHING`（正在搜索设备）状态，没有显示为“等待推流”的黄色等待状态，且 PC 侧的 TCP 监听服务实际上并未成功启动。
* **手机侧**：尝试建立连接时无法完成 TCP 握手，处于等待 PC 连通的阻塞状态。
