## 0. 阶段定义（先看这里）

> 🎯 **当前阶段目标（必须明确）**：
> **MVP 完成时，用户 3 分钟内能在腾讯会议 / OBS 中看到手机画面。**

| 阶段 | 目标 | 验收 |
|------|------|------|
| **MVP-0** | 项目骨架闭环 | 文档完整 + 代码可运行 |
| **MVP-1** | 假视频流闭环 | 用 mock 验证协议 + 接收 + 显示 |
| **MVP-2** | 真实摄像头 | 电脑端 OpenCV 窗口看到手机画面 |
| **MVP-3** | 虚拟摄像头 | 腾讯会议能选 PhoneCam Camera |
| **MVP-4** | 产品化 | 用户照文档 3 分钟内完成首次连接 |

**远期目标（不在 MVP 范围）**：
- 3 秒内启动（理想体验）
- 1080p60（先用 720p30 跑通）
- 端到端 < 80ms（先用 < 300ms 验证链路）
- 音视频同步、WiFi、GUI、EXE/APK 打包

> 🧠 **第一性原理**：本产品的本质是**低延迟视频链路**，不是"手机 App"或"电脑软件"。
> 项目推进应**按链路闭环**，而不是按目录写代码。

## 1. 项目愿景（Vision）

**远期愿景**：3 秒内，让你的手机成为电脑的高质量外接摄像头。

**当前 MVP 目标**：3 分钟内，用户在腾讯会议 / OBS 中看到手机摄像头画面。

> 笔记本摄像头坏了？想要更高清的画面？PhoneCam 让任何一台 Android 手机立刻变成电脑的 1080p 60fps 摄像头，Windows 视频软件（Zoom、腾讯会议、OBS、Teams）开箱即用。

---

## 2. 核心价值（Core Value）

| 价值 | 说明 | 对比 |
|------|------|------|
| 🎥 **画质好** | 1080p 60fps，调用手机原生摄像头 | 优于 90% 笔记本自带摄像头 |
| ⚡ **低延迟** | 自研传输协议，目标端到端 < 80ms | 与 Iriun Webcam 同级 |
| 🔌 **连接自由** | USB 数据线 / WiFi 热点双模式，用户自由选择 | 出门只带数据线也能用 |
| 🔇 **音视频同步** | 画面 + 麦克风同时传输，无需外接麦克风 | 视频会议更自然 |
| 🛠️ **零配置** | 手机装 App、电脑开 EXE，自动发现，扫码/一键连 | 比 Iriun 启动更简单 |

## 4. 使用场景（Use Cases）

### 场景 A：紧急答辩（最典型）
> 晚上 8 点发现笔记本摄像头坏了，明天 9 点要答辩。

1. 同学帮忙借来一台 Android 手机
2. 装上 PhoneCam App
3. 用数据线连电脑，启动电脑端 EXE
4. 30 秒内系统识别出"PhoneCam Camera"虚拟摄像头
5. 在腾讯会议里选择这个摄像头，答辩顺利 ✅

### 场景 B：咖啡厅远程办公
> 在咖啡厅用笔记本开会，希望画面更清晰。

1. 笔记本连接手机的 WiFi 热点
2. 手机打开 PhoneCam App，电脑启动 EXE
3. 自动配对，1080p 60fps 画面出现在 Zoom 中

### 场景 C：直播带货
> 用手机的前置/后置专业镜头做 OBS 直播。

1. 手机固定在三脚架，对准商品
2. USB 连接到直播电脑
3. OBS 添加"PhoneCam Camera"作为视频源
4. 切换前后置摄像头只需在手机上操作

## 5. 核心功能（Core Features）

### 5.1 手机端（Android App）

| 功能 | 详细说明 | 优先级 |
|------|---------|--------|
| 摄像头采集 | 调用 Camera2 API，支持前置/后置切换 | P0 |
| 视频编码 | H.264 硬编码（MediaCodec）| P0 |
| 音频采集 | AudioRecord 采集麦克风，AAC 编码 | P0 |
| **自研协议封装** | 视频 + 音频 + 控制信令统一打包 | P0 |
| 传输通道 | USB（adb forward）/ WiFi 热点 TCP | P0 |
| 手机热点开启 | 一键开启 WiFi 热点（USB 调试模式）| P1 |
| 设置页 | 切换前后置、查看连接状态 | P0 |
| 横竖屏自适应 | 画面自动旋转 | P1 |

### 5.2 电脑端（Windows EXE）

| 功能 | 详细说明 | 优先级 |
|------|---------|--------|
| 手机发现 | mDNS（USB 自动 adb forward / WiFi 局域网扫描）| P0 |
| 连接管理 | USB 与 WiFi 模式切换 UI | P0 |
| 视频解码 | H.264 硬解码（Media Foundation / D3D11VA）| P0 |
| 音频解码 | AAC 解码 | P0 |
| **自研协议解析** | 解析自研协议帧，重组视频音频流 | P0 |
| 虚拟摄像头 | pyvirtualcam 输出系统级摄像头 | P0 |
| 虚拟麦克风 | 输出到系统音频设备（VB-Cable 或类似）| P0 |
| GUI 界面 | 连接状态、分辨率、帧率、模式选择 | P0 |
| 命令行模式 | `phonecam.exe` 一行启动 | P1 |

### 5.3 自研传输协议（核心差异化）

**协议名暂定**：`PCP`（PhoneCam Protocol）

**协议设计目标**：
- 端到端延迟 < 80ms（1080p60 场景）
- 带宽自适应（WiFi 弱信号自动降码率）
- 单一连接同时传输视频 + 音频 + 控制
- 支持可靠控制信令 + 不可靠媒体流

**协议层级**（自下而上）：

```
┌─────────────────────────────────┐
│  应用层：H.264 视频帧 / AAC 音频帧 │  ← 媒体数据
├─────────────────────────────────┤
│  帧封装：序列号 / 时间戳 / 帧类型  │  ← 单帧打包
├─────────────────────────────────┤
│  通道层：视频通道 / 音频通道 / 控制 │  ← 多路复用
├─────────────────────────────────┤
│  传输层：基于 TCP（USB/WiFi）     │  ← 可靠传输
└─────────────────────────────────┘
```

**控制信令类型**：
- 客户端 → 手机：请求关键帧、切换前后置、调整码率
- 手机 → 客户端：连接确认、参数协商、心跳

**为什么不用 MJPEG？**
MJPEG 每帧都是完整图片，1080p60 需要约 100Mbps 带宽，USB 和 WiFi 都撑不住。H.264 关键帧 + 增量帧方案可以把带宽压到 4-8 Mbps。

## 6. 验收标准（Acceptance Criteria）

> 这些标准用来判断"项目是否做完了"。每条都要能客观验证。

### 6.1 功能验收

- [ ] **AC-1**：Android App 能采集前后置摄像头画面
- [ ] **AC-2**：Windows EXE 能输出一个名为"PhoneCam Camera"的虚拟摄像头
- [ ] **AC-3**：在 Zoom 中能看到"PhoneCam Camera"选项并显示手机画面
- [ ] **AC-4**：USB 连接模式下，从摄像头采集到画面显示端到端延迟 < 100ms
- [ ] **AC-5**：WiFi 热点模式下，画面流畅无明显卡顿（30fps 持续）
- [ ] **AC-6**：麦克风音频能传到电脑，在 Zoom 会议中能听到手机麦克风声音
- [ ] **AC-7**：电脑端能控制手机切换前后置摄像头，无需手动操作手机
- [ ] **AC-8**：支持 1080p + 60fps（受限于手机硬件时可降级）

### 6.2 易用性验收

- [ ] **AC-9**：从"双机都是全新状态"到"视频会议看到画面"全程 < 3 分钟
- [ ] **AC-10**：电脑端有 GUI 界面，非技术用户也能完成连接
- [ ] **AC-11**：手机端有清晰的状态指示（未连接 / 等待中 / 已连接）

### 6.3 稳定性验收

- [ ] **AC-12**：连续使用 2 小时无断连、无内存泄漏
- [ ] **AC-13**：网络中断后能在 5 秒内自动重连
- [ ] **AC-14**：手机锁屏后画面仍能继续传输

## 7. 项目边界（Boundaries）

### ✅ 本项目要做
- Android App（最低 Android 7.0 / API 24）
- Windows EXE（Windows 10 1903+ / Windows 11）
- 自研传输协议 PCP
- USB + WiFi 热点两种连接方式
- 视频 + 音频同步传输
- 基础 GUI

### ❌ 本项目不做
- iOS App（仅 Android）
- Linux / macOS 电脑端
- 视频录制 / 截图保存（由 OBS 等软件实现）
- 滤镜 / 美颜（由视频会议软件自带功能）
- 多手机同时连接（仅一对一）
- 商业授权 / 付费功能
- 云服务 / 账号系统（完全本地 P2P）

## 8. 非功能约束（Non-functional Constraints）

| 约束类型 | 详细要求 | 影响 |
|---------|---------|------|
| **延迟** | 端到端 < 100ms（USB 模式）| 协议栈设计、避免 buffer 堆积 |
| **带宽** | 1080p60 视频 < 8Mbps | H.264 编码质量参数、码率自适应 |
| **CPU 占用** | 电脑端 < 15%（1080p60）| 用硬解码、避免软解 |
| **手机发热** | 长时间使用不烫手 | 降低分辨率/帧率的可选项 |
| **安装包大小** | Android APK < 30MB | 避免引入大型库 |
| **依赖** | 电脑端仅需 Python + 虚拟摄像头驱动 | 不依赖 OBS Studio 等大型软件 |
| **隐私** | 视频流不经过任何第三方服务器 | 完全局域网 P2P |

## 9. 风险与挑战（Risks）

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 🪟 Windows 虚拟摄像头驱动兼容性 | 用户可能装了精简版 Windows 没有虚拟摄像头 | 提供驱动安装教程、检测脚本 |
| 🔋 手机电量消耗 | 长时间使用会快速耗电 | 提示用户插电、降低码率 |
| 🐛 ADB 调试首次开启麻烦 | 普通用户不知道 USB 调试在哪 | 提供图文引导、考虑用 ADB Wireless |
| 📶 WiFi 热点信号不稳定 | 咖啡厅/地铁里可能频繁断连 | 实现快速重连、提示用户用 USB |
| 🔐 USB 权限弹窗 | 每次连接都要弹窗授权 | 用 ADB 密钥持久化、首次配置后无感 |
