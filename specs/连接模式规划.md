# 连接模式规划

> 📡 PhoneCam 支持的连接方式及其技术选型。

---

## 连接模式总览

| 模式 | 用户操作 | 技术方案 | 状态 |
|------|---------|---------|------|
| **USB + adb** | 插 USB 线 + 开 USB 调试 | adb reverse tcp:9999 | ✅ 当前方案（开发阶段）|
| **USB 直连** | 插 USB 线（无需 USB 调试）| 原生 USB 驱动 | 📋 规划中 |
| **热点模式** | 手机开热点 → PC 连热点 | TCP 直连（手机 IP 固定 192.168.43.1）| 📋 规划中 |
| **WiFi 路由器** | 手机和 PC 连同一 WiFi | TCP 直连（需发现 PC IP）| 📋 规划中 |

---

## 模式 1：USB + adb（当前方案）

**原理**：adb reverse 把手机的 localhost:9999 映射到 PC 的 localhost:9999。

```
手机 → 127.0.0.1:9999 → USB 线 → adb reverse → PC:9999
```

**优势**：
- Hermes（AI agent）可以通过 adb 命令自主联调
- 所有用户 PC 的地址都是 127.0.0.1:9999（统一）
- 开发调试效率最高

**劣势**：
- 用户需要安装 adb、开启 USB 调试
- 不是最终产品形态

**定位**：开发阶段工具，不是最终产品。

---

## 模式 2：USB 直连（规划）

**原理**：用 Android Open Accessory (AOA) 协议或 RNDIS 驱动，让 PC 和手机通过 USB 线直接建立网络连接，不需要 adb。

**优势**：
- 用户不需要安装 adb 或开启 USB 调试
- 插线即连，体验最好

**劣势**：
- 开发成本高（需要写 PC 端 USB 驱动或用 libusb）
- Hermes 无法通过命令行调试（没有 adb）
- Windows 驱动签名问题

**定位**：最终产品可选方案。开发阶段用 adb 代替。

---

## 模式 3：热点模式（规划，优先级最高）

**原理**：手机开 WiFi 热点，PC 连接热点，形成点对点局域网。手机 IP 固定为 192.168.43.1（Android 默认热点网关）。

```
手机（热点）192.168.43.1 ←→ PC 192.168.43.x
TCP 直连，不需要互联网
```

**优势**：
- 不需要路由器、不需要互联网、不需要 adb
- 手机 IP 固定（192.168.43.1），PC 端直接连这个地址
- 延迟最低（直连，不经过路由器）
- 无 SIM 卡也能用
- 用户操作：开热点 → PC 连热点 → 打开 PhoneCam

**劣势**：
- PC 连接手机热点后，PC 的互联网会断（走手机热点通道）
- 手机热点耗电

**连接方向**：PC 作为客户端连接手机（手机 IP 固定为 192.168.43.1）。

**与当前架构的关系**：
- 当前：手机端 TcpStreamServer 先尝试 Client 模式连 PC，失败降级 Server
- 热点模式：手机端作为 Server 监听 9999，PC 端作为 Client 连接 192.168.43.1:9999
- 需要修改：PC 端 ConnectionManager 增加"热点模式"，主动连接手机

---

## 模式 4：WiFi 路由器（规划）

**原理**：手机和 PC 连同一个 WiFi 路由器，通过局域网 TCP 连接。

**优势**：
- 不需要 adb、不需要 USB 线
- PC 和手机都可以同时上网

**劣势**：
- 需要知道 PC 的 IP 地址（DHCP 分配，会变）
- 需要某种发现机制（UDP 广播 / mDNS / 用户手动输入）
- 延迟比热点模式高（经过路由器）

**IP 发现方案**（待决策）：

| 方案 | 用户操作 | 技术复杂度 | 可靠性 |
|------|---------|-----------|--------|
| 用户手动输入 IP | 手机端输入 PC 的 IP | 低 | 高 |
| UDP 广播发现 | 零配置 | 中 | 中（受 AP 隔离影响）|
| mDNS/Bonjour | 零配置 | 中 | 中（依赖系统服务）|

---

## 连接顺序问题

**当前问题**：手机端只尝试一次 Client 连接，失败就永久降级 Server 模式。

**解决方案**：手机端 loop 重试 Client 连接（每 3 秒一次），直到成功。不管谁先启动都能连上。

**长期方案**：热点模式下方向固定（PC 连手机），不存在顺序问题。

---

## 实施优先级

1. **Loop 重试**（1 小时）— 修复当前 USB + adb 的顺序问题
2. **热点模式**（1-2 天）— 最实用的无线方案，用户只需开热点
3. **WiFi 路由器模式**（3-5 天）— 需要 IP 发现机制
4. **USB 直连**（可选）— 开发成本高，adb 暂时够用
