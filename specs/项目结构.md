# PhoneCam 项目结构

> 🏗️ **本文档作用**：定义每个目录的**职责**和**放置规则**。
> 项目结构遵循"**按受众分类**"原则：每个目录只服务一类受众。

---

## 1. 设计原则

| 原则 | 含义 |
|------|------|
| **按受众分** | 不同角色（用户/开发者/AI）只看自己需要的目录 |
| **职责单一** | 一个目录只承担一类职责，不混杂 |
| **链路可见** | 视频链路涉及的所有文件能在 1-2 跳内找到 |
| **演进友好** | MVP 阶段简洁，未来加模块不破坏现有结构 |

---

## 2. 顶层结构

```
PhoneCam/
├── .ai/                  🤖 AI 助手专用上下文
├── docs/                 📖 人类可读的文档（用户/新人）
├── specs/                📋 产品规范（人 + AI 共用）
├── desktop/              💻 电脑端源码
├── phone/                📱 旧 Flutter 工程（LEGACY，已冻结 ADR-006）
├── phone_native/         📱 MVP-2 Kotlin 原生最小 App 工程
├── tests/                🧪 测试中间件
├── scripts/              🔧 跨端构建/安装脚本
├── LICENSE
└── README.md             🏠 项目入口
```

## 3. 各目录详解

### 3.1 `.ai/` — AI 助手上下文

> 谁会读：**AI 助手**（每次会话开始时）
> 什么时候更新：**每次重大决策后**

```
.ai/
├── context.md            # 项目记忆：是什么、进度、用户水平
├── decisions.md          # 决策记录（ADR）：为什么选这个技术
├── code-style.md         # 编码规范：命名、注释、提交信息
└── prompts/              # 提示词模板
    ├── code-review.md    # 审查代码时
    ├── bug-fix.md        # 修 bug 时
    └── feature.md        # 实现新功能时
```

**规则**：
- ❌ 业务代码不放在这里
- ❌ 用户看的文档不放在这里
- ✅ 仅放"让 AI 快速理解项目"的元信息

---

### 3.2 `docs/` — 人类可读文档

> 谁会读：**用户、新人贡献者、未来 6 个月后的自己**

```
docs/
├── README.md             # 文档入口（按需创建）
├── user-manual.md        # 用户使用手册（如何安装使用）
├── installation.md       # 安装指南
├── troubleshooting.md    # 故障排查
├── architecture.md       # 架构图（人类可读版）
├── protocol.md           # PCP 协议说明
└── optimization-plan.md  # 优化计划
```

**规则**：
- ✅ 用"人话"写，避免技术黑话堆砌
- ✅ 配图、流程图、表格
- ❌ 不放 API 参考（应在代码 docstring 里）

---

### 3.3 `specs/` — 产品规范

> 谁会读：**产品决策者、架构师、AI**
> 什么时候更新：**当产品方向、技术选型、阶段计划有变化时**

```
specs/
├── 产品概述.md           # Vision、目标用户、场景、边界
├── 技术栈.md             # 每个模块用什么库
├── 项目结构.md           # 本文档
└── MVP路线图.md          # MVP-0 到 MVP-4 的分阶段计划
```

**规则**：
- ✅ 这是项目的"宪法"，是其他文档的源头
- ✅ 每个 spec 文档是"决策性"的，不重复细节
- ❌ 不放实现细节、API 文档

---

### 3.4 `desktop/` — 电脑端源码（Python）

> 负责：**接收 PCP 协议、解码 H.264、输出虚拟摄像头**

```
desktop/
├── phonecam.py              # 主入口
├── connection_manager.py    # 连接管理（USB/网络）
├── discovery.py             # mDNS 自动发现
├── receiver.py              # TCP 接收 + 协议解析
├── h264_decoder.py          # H.264 硬解码（PyAV）
├── h264_receiver.py         # H.264 帧处理（旧版，可移除）
├── virtual_camera.py        # pyvirtualcam 输出
├── usb_handler.py           # USB 反向网络（adb forward）
├── gui.py                   # tkinter GUI（后期）
├── requirements.txt         # Python 依赖
│
├── tests/                   # 电脑端单元测试
│   ├── __init__.py
│   └── test_receiver.py
│
└── scripts/                 # 电脑端构建脚本
    └── build_exe.py         # PyInstaller 打包
```

**关键文件说明**：

| 文件 | 职责 | MVP 阶段 |
|------|------|---------|
| `phonecam.py` | CLI 入口、参数解析、调用其他模块 | MVP-1 |
| `receiver.py` | **PCP 协议解析核心** | MVP-1 |
| `h264_decoder.py` | H.264 → RGB 帧 | MVP-2 |
| `virtual_camera.py` | RGB 帧 → 系统摄像头 | MVP-3 |
| `gui.py` | tkinter 窗口 + 控制 | MVP-4 |

**模块依赖**（自上而下）：

```
phonecam.py
   ↓
connection_manager.py ──→ discovery.py
   ↓                      ↓
receiver.py            usb_handler.py
   ↓
h264_decoder.py
   ↓
virtual_camera.py
```

### 3.5 `phone/` — 手机端源码（Flutter/Dart）

> 负责：**采集摄像头、H.264 硬编码、PCP 协议封装、TCP 发送**

```
phone/
├── lib/                       # Dart 源码
│   ├── main.dart              # App 入口
│   ├── camera_service.dart    # 摄像头采集
│   ├── h264_encoder.dart      # H.264 软封装（数据流转 Kotlin）
│   ├── stream_server.dart     # HTTP/WS 服务（PCP 载体）
│   ├── discovery_service.dart # mDNS 广播
│   ├── usb_service.dart       # USB 反向网络管理
│   └── ui/
│       ├── home_page.dart     # 主页（连接状态、按钮）
│       └── settings_page.dart # 设置页（分辨率/帧率）
│
├── android/                   # Android 原生工程
│   └── app/src/main/kotlin/com/phonecam/phone/
│       ├── MainActivity.kt            # Flutter Activity
│       └── H264EncoderPlugin.kt       # ⭐ MediaCodec 硬编码
│
├── ios/                       # iOS 工程（不发布但保留）
│
├── test/                      # 单元测试
│   └── widget_test.dart
│
├── scripts/                   # 手机端构建脚本
│   └── build_apk.ps1
│
└── pubspec.yaml               # Flutter 依赖
```

**关键文件说明**：

| 文件 | 职责 | MVP 阶段 |
|------|------|---------|
| `main.dart` | App 启动、初始化 | MVP-0 |
| `camera_service.dart` | 摄像头采集回调 | MVP-2 |
| `h264_encoder.dart` | Dart 侧编码接口（调用 Kotlin）| MVP-2 |
| `H264EncoderPlugin.kt` | ⭐ **Android MediaCodec 硬编码** | MVP-2 |
| `stream_server.dart` | HTTP/WS 服务、PCP 打包 | MVP-1/MVP-2 |
| `usb_service.dart` | USB 反向网络 | MVP-1 |

## 4. 视频链路文件地图

> 一次完整的"手机画面到电脑屏幕"涉及哪些文件

```
📱 手机端
  phone/lib/camera_service.dart           ← 摄像头原始 YUV
       ↓
  phone/lib/h264_encoder.dart             ← 调 Kotlin
       ↓
  phone/android/.../H264EncoderPlugin.kt  ← MediaCodec 硬编码 H.264
       ↓
  phone/lib/stream_server.dart            ← PCP 协议打包
       ↓
  TCP socket

🌐 网络层（USB 反向网络 或 WiFi 局域网）

💻 电脑端
  desktop/receiver.py                     ← TCP 接收 + PCP 解包
       ↓
  desktop/h264_decoder.py                 ← PyAV 硬解码 H.264 → RGB
       ↓
  desktop/virtual_camera.py               ← pyvirtualcam 输出
       ↓
  Windows 虚拟摄像头驱动 (OBS Virtual Camera)
       ↓
  Zoom / 腾讯会议 / OBS 看到画面
```

**一图流的关键检查点**（每个都要在对应阶段验证）：

| 检查点 | 文件 | MVP 阶段 |
|--------|------|---------|
| 摄像头能采到帧 | `camera_service.dart` | MVP-2 |
| 编码能产出 H.264 | `H264EncoderPlugin.kt` | MVP-2 |
| PCP 协议能发包 | `stream_server.dart` | MVP-1 |
| 电脑能收到包 | `receiver.py` | MVP-1 |
| 能解出 RGB 帧 | `h264_decoder.py` | MVP-2 |
| 能输出到虚拟摄像头 | `virtual_camera.py` | MVP-3 |
| 会议软件能识别 | （系统层面）| MVP-3 |

## 5. 文件命名规范

### Python
- 模块：`snake_case.py`（如 `connection_manager.py`）
- 类：`PascalCase`（如 `ConnectionManager`）
- 函数/变量：`snake_case`（如 `start_server`）
- 私有：前缀下划线（`_internal_state`）

### Dart
- 文件：`snake_case.dart`（如 `stream_server.dart`）
- 类：`PascalCase`（如 `StreamServer`）
- 公开方法/变量：`camelCase`（如 `startServer`）
- 私有：前缀下划线（`_wsClient`）

### Kotlin
- 文件：`PascalCase.kt`（如 `H264EncoderPlugin.kt`）
- 类：`PascalCase`（如 `H264EncoderPlugin`）
- 函数/变量：`camelCase`（如 `encodeFrame`）
